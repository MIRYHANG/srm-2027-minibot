# srm-2027-minibot

2027 校内赛抓取小车的控制程序。仓库里有两个工程：

- **小车主控**（仓库根目录）：STM32G474VET6，STM32Cube HAL、FreeRTOS（CMSIS-RTOS v1）、CMake
- **NRF24 手柄**（`Handheld/`）：STM32F103RC，裸机循环

两边共用的无线收发和手柄数据包代码放在 `Common/`。

以下内容按 2026-11-02 的 `power-on-debug` 分支整理。

## 小车软件结构

### 任务

| 任务 | 周期 | 优先级 | 职责 |
|---|---|---|---|
| `ProtocolTask` | 5 ms | AboveNormal | 收手柄和手机数据，读急停和欠压，处理使能和换挡，发布最新命令，回传状态给手柄 |
| `ChassisControlTask` | 10 ms | High | 麦轮解算、编码器测速、四轮速度 PI、输出 PWM；检查各任务心跳并喂看门狗 |
| `ArmTask` | 20 ms | Normal | 按命令点动或切换预设，限速逼近目标，换算成 6 路舵机脉宽 |
| `SensorTask` | 100 ms | Low | 读 INA226 电压电流、电池电量判断、刷新 OLED |

### 数据链路

```text
手柄摇杆和按键（每 10 ms 发一包，NRF24 2.500 GHz）
  → 小车 NRF24 接收，校验数据包
  → RemoteInput：选定遥控来源，超时 100 ms 判掉线
  → SafetyInput：急停、欠压
  → RobotCmd：使能锁存、换挡，生成底盘命令和机械臂命令
  ├→ ChassisDrive：按挡位换算四轮目标转速 → 编码器测速 → 速度 PI → TIM1 PWM 和方向引脚
  └→ ArmCycle：点动或预设 → 限位、限速 → 舵机脉宽 → TIM8 / TIM15
```

遥控来源在编译时选择：`Core/Src/app_freertos.c` 里的 `REMOTE_ACTIVE_SOURCE`，当前是 `REMOTE_SOURCE_HANDHELD`。改成 `REMOTE_SOURCE_PHONE` 就用手机蓝牙（USART2，9600 波特率，超时 200 ms）。

### 安全机制

- **使能要先失能再使能**：上电、急停解除或掉线恢复后，必须先收到一次"未使能"，再收到"使能"，小车才会动，防止手柄一直锁在使能状态时车自己跑起来。
- **掉线停车**：手柄超过 100 ms 没有有效数据包，底盘目标清零、PID 清零、PWM 归零；机械臂停在当前位置但保持出力。
- **硬件急停**：PE10 为低时整车失能。急停线同时接在四个驱动芯片的 nSLEEP 上，按下时驱动直接关断输出。
- **欠压保护**：3S 电池，单节低于 3.50 V（共 10.5 V）报警，低于 3.30 V（共 9.9 V）停车，带 0.1 V/节回差和 2 s 确认时间。
- **任务心跳和看门狗**：底盘任务确认其他三个任务都按时打了心跳才喂 IWDG，超时约 100 ms 整机复位。调试暂停时 IWDG 和 TIM1 冻结。
- **异常停机**：HardFault、`Error_Handler`、断言失败、栈溢出、内存分配失败都会直接关掉四路电机 PWM。
- **复位记录**：`g_reset_stats` 放在不初始化的 `.noinit` 段，按原因（引脚、欠压/上电、看门狗、软件）累计复位次数，在 Ozone 里能看到。

## 手柄操作

| 按键 | 作用 |
|---|---|
| START | 使能小车；同时把机械臂方向复位成正向、解除机械臂停止 |
| ESTOP | 失能小车，按下立刻生效 |
| 摇杆 | 前后、左右平移 |
| 摇杆按下 | 换挡 1 → 2 → 3 → 1，每次使能回到 1 挡 |
| CCW / CW | 按住时逆时针 / 顺时针自转 |
| J1～J5、GRIPPER | 按住时对应关节按当前方向点动 |
| ARM_DIR | 单按切换点动方向；按住时再按 J1 回收起姿态，按 J2 进入抓取准备姿态 |
| ARM_STOP | 只停机械臂，按 START 解除 |

解锁顺序：按一下 ESTOP 松开，再按 START。

| 指示灯 | 含义 |
|---|---|
| LED1 灭 / 慢闪 / 常亮 / 快闪 | 断连 / 已连上未使能 / 已使能 / 小车急停或驱动故障 |
| LED2 灭 / 常亮 / 快闪 | 机械臂正向 / 反向 / 已停止 |
| 两灯同时快闪 | 摇杆没标定好（上电时摇杆被推着）或 ADC 异常，手柄强制失能 |

## 临时措施与已知问题

以下是为了先让车动起来而做的临时处理，硬件改好后要恢复。

1. **驱动故障检测被屏蔽。** DRV8873H 的 nOL 引脚接了地，会打开运行中的开路检测；电机电流或占空比小时会误报并锁住 nFAULT，但 H 桥照常输出。误报会让整车失能，所以 `MOTOR_FAULT_IGNORE_MASK` 暂时屏蔽了四路 nFAULT。过流和过热仍由驱动芯片自己关断。
   - 硬件改法：四个驱动的 nOL 改接 DVDD。
   - 改好后把 `MOTOR_FAULT_IGNORE_MASK` 改回 `0U`。
2. **机械臂限位暂时放开到 0～180°**，方便实物标定。标定出各关节真实的机械范围后要收回来，否则可能顶坏结构。
3. **驱动芯片损坏过**：10-30 FL 驱动芯片损坏，FL 电机不受控狂转，已更换新芯片，现在四轮正常。调试中 RR 也出现过程序没运行时电机自转的现象。驱动先后出问题，可能是电机刹车时反电动势把 VM 冲高，建议每个驱动旁加 100～470 µF 电解电容。
4. **舵机堵转导致复位和烧毁**：10-31 六个舵机一起上电，几个舵机堵转把主控拉复位，一个舵机烧毁。更换全部降压电路后恢复正常。
   - 原因：上电时 6 个舵机会同时全速转到收起姿态。这组角度是装机前填的占位值，可能让机械臂顶到结构上而堵转。
   - 建议：先在实物上量出收起姿态的角度，写进代码；舵机单独用一路大电流降压供电，并在舵机电源上加大电容。
5. **接 J-Link 时会复位**：Ozone 下载、复位或两个程序同时连 J-Link 都会让主控复位；装上机械臂后，J-Link 接着一段时间也会复位（J-Link 没有接 3.3V）。拔掉 J-Link 后实测 5 分钟没有复位。因为这个问题，预设姿态还没法在 Ozone 里看着舵机角度实测。
   - 复位脚现在飞线接到了 3.3V。如果中间没有串电阻，按复位键会直接把 3.3V 对地短路，看门狗和 J-Link 也拉不低复位脚。建议改成 10 kΩ 上拉到 3.3V，再并 100 nF 电容到地。
6. **电机噪声**：速度环每 10 ms 测一次速，多数或少数一个编码器计数，测出的转速就差约 4.5 rpm，速度环输出会小幅来回跳动。可以加大测速滤波或给误差加死区，还没改。

## 构建、烧录和测试

需要 `arm-none-eabi-gcc`、CMake、Ninja；测试需要电脑上的 `gcc`。

```bash
# 小车固件，产物 build/Debug/XiaoSai.elf
cmake --preset Debug
cmake --build build/Debug

# 手柄固件，产物 Handheld/build/Debug/XiaoSai_NRF.elf
cd Handheld
cmake --preset Debug
cmake --build build/Debug

# 电脑端单元测试（仓库根目录运行）
bash tools/run_host_tests.sh
```

烧录和调试用 J-Link + SEGGER Ozone，直接打开 `XiaoSai.jdebug`（小车）或 `Handheld/XiaoSai_NRF.jdebug`（手柄）。工程里预置了常用观察变量，按 10 Hz 实时刷新。这个 J-Link 不支持高速采样，Data Sampling 用不了，看波形要用 Watched Data。

修改引脚、定时器等外设配置时，以 `XiaoSai.ioc` / `Handheld/XiaoSai_NRF.ioc` 为准，用 CubeMX 重新生成；自己写的代码放在 USER CODE 区或独立模块里。

#### 当前数据链路

```text
USART2 接收一个字节
  → 中断回调将字节和接收时间放入队列
  → 底盘任务按处理预算取出字节
  → RemotePhone_ProcessByte 拼帧、校验、解码和转换
  → RemoteInput 保存手机命令和有效帧时间
  → RemoteInput_GetSafe 检查来源、超时、使能和停机请求
  → Chassis_UpdateFromRemote 换算底盘速度
  → 麦轮解算得到四轮目标 RPM
  → 编码器测速与 PID 计算
```

- 中断只接收和暂存数据，协议解析与遥控状态修改由同一个底盘任务完成
- 队列容量为 64 个接收记录，每个记录包含一个字节和毫秒时间戳
- 每个任务周期最多处理 64 个字节，不是 64 帧
- 时间戳使用字节接收回调中的 `HAL_GetTick()`，不是任务稍后处理字节的时间
- 只有完整有效的控制帧才会更新 `last_valid_ms`
- 掉线、未使能、停机请求或接收异常时，当前安全遥控命令归零
- 接收异常时清空手机旧状态并重置解析器，恢复后必须等待新的有效帧

#### 当前运行限制

- 底盘任务周期为 10 个 RTOS tick，当前 tick 频率为 1000 Hz，对应约 10 ms
- 底盘尺寸、速度上限和 PID 增益仍为零占位，不产生正常运动目标
- `WheelSpeed_Update()` 目前只计算 PID，尚未将输出交给 `Motor_SetOutput()`
- `Chassis_Stop()` 尚未实现，目标 RPM 归零不能代替实际 PWM 停机与 PID 状态清理
- 手机无线串口模块到小车的真实链路、四轮闭环及六路舵机均未完成实物联调
- 今日新增接收与任务链路尚未记录编译、上板运行及异常注入测试结果
