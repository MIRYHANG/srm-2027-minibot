## 整车工程架构

本工程用于 2027 校内赛抓取小车，目标是让麦克纳姆轮底盘运送矿石，并用五个关节加一个夹爪完成抓取与放置。主控为 STM32G474VET6，软件使用 STM32Cube HAL、FreeRTOS CMSIS-RTOS v1、CMake 和 CLion。以下按 2026-10-03 的代码说明实际进度；“计划”表示尚未接入运行链路。

### 软件分层

| 目录 | 职责 | 当前内容 |
| --- | --- | --- |
| `Core/` | CubeMX 生成的启动、时钟、引脚、外设和 RTOS 入口 | `main.c` 初始化外设，`app_freertos.c` 创建底盘任务，异常处理进入急停 |
| `BSP/` | 把硬件操作封装成可调用接口 | 四电机 PWM 与方向、四编码器、六舵机、底盘急停；`oled.c` 目前只有空壳 |
| `Algorithm/` | 与具体引脚无关的计算 | 麦轮速度解算、速度 PID |
| `Protocol/` | 串口帧格式与校验 | SRM 协议逐字节解析、CRC、CONTROL 与 PRO_CONTROL 编解码 |
| `Application/` | 把输入变为整车行为 | 手机串口接收与命令转换、遥控来源管理、机械臂目标姿态和标定 |
| `Test/` | PC 端逻辑测试 | 麦轮解算、遥控输入、机械臂标定三组测试 |

`CMakeLists.txt` 把用户模块和 `cmake/stm32cubemx` 中的生成代码一起编译成 `XiaoSai.elf`。修改引脚、定时器和 IWDG 等配置应以 `XiaoSai.ioc` 为来源，再检查 CubeMX 生成结果。自写逻辑尽量留在独立模块或 USER CODE 区。

### 上电与周期任务

1. `main()` 初始化 HAL、系统时钟、GPIO、TIM、SPI1、USART2、I2C2 和 IWDG，然后创建 FreeRTOS 对象并启动调度器。
2. `MX_FREERTOS_Init()` 绑定六个舵机对象、清空机械臂目标，并创建一个 `StartChassisControlTask`。目前没有单独的机械臂、显示或传感器任务。
3. 底盘任务启动四路电机 PWM、四路编码器和 PID，并启动手机串口接收。任务循环每 10 个 RTOS tick 运行一次；当前 RTOS tick 为 1 ms，所以目标周期约 10 ms。
4. 每轮循环在 `osDelayUntil()` 返回后喂一次 IWDG，再计算实际采样时间、处理手机数据并更新底盘。喂狗表示该任务按期醒来，尚不能证明其他未来任务也正常。

### 底盘控制链路

`USART2 字节中断 → 接收队列 → 手机协议解析与 CRC → 遥控命令安全检查 → 期望底盘速度 → 四轮目标 RPM → 编码器测速 → 速度 PID → TIM1 PWM 和方向 GPIO`

中断回调只记录接收字节和到达时间，并放入长度为 64 的队列。底盘任务每周期最多处理 64 个字节，完整有效的 CONTROL 帧才会更新手机命令及时间戳。`RemoteInput_GetSafe()` 在无有效帧、超过 200 ms、未使能或请求停机时返回零命令。串口出错或队列溢出时，会清空旧状态并在任务中尝试恢复接收。

麦轮解算接收前后速度、横移速度和旋转角速度，输出 FL、FR、RL、RR 四轮目标转速。每个车轮由独立编码器测得 RPM，PID 根据目标和实测 RPM 算出电机输出；`Motor_SetOutput()` 将输出符号写到方向引脚、大小写到 TIM1 占空比。停机分支会将目标转速和四路 PWM 清零，并清除 PID 动态状态。

当前底盘尺寸、三项速度上限以及四组 PID 增益仍为零占位，因此代码链路虽已接通，不能据此认为小车已经能正常行驶。`RemoteInput_t` 有手机和自制手柄两路状态，但任务初始化时固定选择手机；自制手柄接收和切换界面尚未实现。协议层具备 PRO_CONTROL 编解码，当前手机处理链路仍只消费 CONTROL 帧。

### 机械臂控制链路

机械方案为五个关节 J1～J5 加一个夹爪，共六个 MG996R 180 度舵机。`ArmPose_t` 用六个元素保存目标：J1～J5 以度为单位，夹爪使用 0～1 的开合比例。`ArmControl` 保存或清除目标姿态；`ArmPose_IsValid()` 按标定范围检查六个目标；`ArmCalib_ToPulse()` 将目标线性换算为 PWM 脉宽。`Servo` BSP 负责设置脉宽和启动对应定时器通道。

| 机构 | 暂定目标范围 | 当前 PWM 通道 | 状态 |
| --- | --- | --- | --- |
| J1 | 0～180 度 | TIM8 CH1 | 待实物标定零位和方向 |
| J2 | 30～90 度 | TIM8 CH2 | 待实物标定零位和方向 |
| J3 | 30～180 度 | TIM8 CH3 | 待实物标定零位和方向 |
| J4 | 90～180 度 | TIM8 CH4 | 待实物标定零位和方向 |
| J5 | 0～180 度 | TIM15 CH1 | 待实物标定零位和方向 |
| 夹爪 | 0～1 比例 | TIM15 CH2 | 待确定实际开合端点 |

六路舵机的底层允许脉宽为 500～2500 μs；标定表另设各关节可用范围和端点脉宽。夹爪目前暂用 1000～2000 μs。当前任务只完成舵机对象绑定，没有调用 `Servo_Start()`，也没有把 `ArmControl` 的目标持续输出到舵机。因此机械臂控制链路仍是“数据结构与驱动接口已具备，任务接线待完成”。

计划中的自制遥控操作是六个按键分别控制 J1～J5 和夹爪，第七个按键每按下一次切换所有舵机的运动方向。方向键应按“由松到按”的边沿识别，按住期间连续收到多帧只能切换一次。按住某个舵机键时，按周期和标定速度增减对应目标，并裁剪到该关节限位；松开后停止改变目标，保持舵机 PWM。该七键逻辑目前尚未写入代码。

### 故障保护

底盘任务正常运行时周期喂 IWDG；按当前预分频和重装值、以约 32 kHz LSI 估算，看门狗超时约 101 ms。HardFault 等五类异常、`Error_Handler`、`configASSERT`、栈溢出和内存分配失败都会调用 `Safety_EmergencyStop()`。该函数直接清 TIM1 四路比较值和 MOE，再把四个 PWM 引脚改为低电平普通输出，同时拉低方向引脚。它不依赖 HAL、RTOS 或中断，且只关闭底盘输出。

急停函数不会关闭 TIM8、TIM15；不过死循环之后 IWDG 整机复位会中断舵机 PWM。因此“异常后机械臂持续保持力矩”目前没有得到保证，需要结合机构和供电实物验证。调试时已配置 TIM1 与 IWDG 在断点暂停期间冻结。
